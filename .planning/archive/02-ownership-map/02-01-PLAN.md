SECTION 2 — Enumerate all variables: `proc contents data=src._all_ out=work.allvars (keep=memname name type length varnum) noprint; run;` then a DATA step writing a NEW dataset that subsets to the eight sources and adds uppercase keys:
```sas
data work.allvars_src;
  set work.allvars;
  where upcase(memname) in
    ('MASTER_DATA_1','MASTER_DATA_2','MASTER_DATA_3','MASTER_DATA_4',
     'MASTER_DATA_5','MASTER_DATA_6','MASTER_DATA_7','MASTER_DATA_8');
  name_u    = upcase(name);
  memname_u = upcase(memname);
run;
```
Two things are load-bearing here and both have bitten this project already:

1. **The operator must be `IN`, never `IN:`.** `IN:` compares on prefix, so
   `MASTER_DATA_7B` matches the literal `'MASTER_DATA_7'` and the stale `master_data_7b`
   artifact is readmitted — defeating RESEARCH Pitfall 1 entirely. Stale artifacts
   (`master_data_all`, `master_data_dedup`, `master_data_merged`, `master_data_7b`) from
   the pre-GSD ad-hoc work may still sit in the P: folder.
2. **Write to `work.allvars_src`, not back into `work.allvars`.** `data X; set X;` is
   prohibited by PCM-R-01 — the rule PCM-T-02 produced. Keeping the raw enumeration means
   a wrong filter costs nothing to correct.

Everything downstream (Section 3 here, Sections 5 and 6 in Plan 02) reads
`work.allvars_src`.

SECTION 3 — Build ownership assignments into `work.ownership_map` with columns `varname $32`, `owner $12`, `n_sources 8`, `sources_present $40`, `coalesce_flag $1`. Use PROC SQL grouped by `name_u`: `count(distinct memname_u) as n_sources`, and build `sources_present` with the exact catx('|', min(case when memname_u='MASTER_DATA_1' then 'md1' end), ... md8 ...) pattern from RESEARCH Pattern 2. Set `owner` = the single md label when n_sources=1; when n_sources>1 set `owner='CONFLICT'` (Plan 02 resolves specific owners). Initialise `coalesce_flag='N'` for all rows in this plan (Plan 02 flips BMI/RACE to 'Y'). Sort the result by varname.

SECTION 4 — Write two artifacts:

      **Column arithmetic:** `sources_present` holds up to `md1|md2|md3|md4|md5|md6|md7|md8` = 31 chars. A `$40.` field at @58 would run to column 97 and collide with anything at @82, silently truncating the source list for exactly the variables that appear in the most sources. `$32.` at @58 ending by column 89, with the next field at @95, leaves clearance.
