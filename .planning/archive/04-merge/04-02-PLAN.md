  Expected: the first dataset name appearing after the MERGE keyword is work.sort_prep_md3.
  Fail condition: any other dataset appears first.

CHECK 2 -- All eight datasets present with IN= and KEEP=:
  grep -c "in=in[1-8] keep=PRECEDE_STUDY_ID &keep" sas/04_merge.sas
  Expected: returns 8. Every source must have BOTH an IN= flag (provenance, MRG-03) and a

CHECK 3 -- Provenance flag assignment after BY:
  grep -in "in_md1 = in1" sas/04_merge.sas
  Expected: returns 1 line.

CHECK 4 -- NO _d_ rename scheme:
  grep -c "_d_" sas/04_merge.sas
  Expected: returns 0. The `_d_varname_mdN` suppression scheme overflows SAS's 32-character
  variable-name limit (SEV_EXP_INTRAOP_MAC_MINUTES_TOTA -> 39 chars, and a dozen more) and
  will not compile. Ownership is enforced by KEEP=, so there is nothing to rename or drop.

CHECK 5 -- No &SQLOBS:
  grep -in "&SQLOBS" sas/04_merge.sas
  Expected: returns 0 lines. Any match is a PCM violation -- fix by replacing with
  SELECT COUNT(*) INTO :macvar TRIMMED.

CHECK 6 -- No PROC SQL UPDATE (MULTI-LINE -- a single-line grep cannot see this):
  grep -A5 -i "proc sql" sas/04_merge.sas | grep -in "^[[:space:]]*update "
  Expected: returns 0 lines.
  An earlier draft used `grep -in "proc sql update"`, which can NEVER match: the statement is
  written `proc sql;` on one line and `update ...` on the next. That check was non-functional.

CHECK 7 -- No in-place rewrite (MULTI-LINE -- same problem):
  grep -A2 -i "data g.master_data_merged" sas/04_merge.sas | grep -in "set g.master_data_merged"
  Expected: returns 0 lines.
  An earlier draft grepped `data g\.master_data_merged.*;` and expected exactly 1 match. But
  `data g.master_data_merged; set g.master_data_merged;` on ONE line yields exactly 1 match and
  PASSES — while being precisely the PCM-T-02 violation the check exists to catch.

CHECK 8 -- %abort cancel inside macro definitions only:
  Confirm every `%abort cancel` lies between a `%macro` and its matching `%mend` (PCM-R-05).

CHECK 9 -- Assertions coded:
  grep -c "assert_eq" sas/04_merge.sas            -- expected >= 15 (1 definition + 14 calls)
  grep -c "expected=41150" sas/04_merge.sas       -- expected >= 3 (rows, distinct IDs, in_md3)
  grep -c "expected=0" sas/04_merge.sas           -- expected >= 4 (blank key, sentinel, 2 ownership)
  grep -c "expected=14778" sas/04_merge.sas       -- expected >= 2 (in_md1 + in_md2)

CHECK 10 -- qc/04_merge_provenance.txt write is coded:
  grep -in "04_merge_provenance.txt" sas/04_merge.sas
  Expected: returns >= 1 line.

CHECK 11 -- LENGTH before MERGE in the DATA step:
  grep -n "length\|merge work" sas/04_merge.sas
  Expected: the lowest-numbered line containing "length" appears before the lowest-numbered
  line containing "merge work.sort_prep_md3".

CHECK 12 -- Keep lists are generated, not transcribed:
  grep -q "qclib.ownership_map" sas/04_merge.sas && grep -q "build_keeplists" sas/04_merge.sas

  and duplicates the Phase 2 artifact built for this purpose.

  grep -n "Emergent \$4\|Intraop_Ketamine \$4\|Preop_block \$4" sas/04_merge.sas
  Expected: returns 0 lines. md3 owns all three at $1; md8's $4 copies are not kept.

If any check fails, fix sas/04_merge.sas before proceeding. Document each fix in the task output.
