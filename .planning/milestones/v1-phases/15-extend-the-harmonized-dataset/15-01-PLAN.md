<objective>
Satisfy HARM-04: every canonical-name decision is recorded in `concept_decisions.csv`,
attributed and dated, and applied by program rather than by hand.

Phase 14 produced `docs/concept_decisions_EXT_TEMPLATE.csv` (value-level rows for the SSDI
death family and the CPT1 code/label pair) and `docs/label_similarity_candidates.csv` (label
sweep candidate pairs). This plan is the HUMAN DECISION step that HARM-04 requires: a human
screens each concept against the 10b gates that cannot be satisfied by review alone, reviews
the evidence, marks CONFIRMED=YES on the concepts they accept, appends those rows to the main
`concept_decisions.csv`, and records the provenance (who, when, what, and what was deferred)
in DECISIONS.md.

No SAS code is written here. The existing `10b_concept_harmonize.sas` machinery (13 validation
gates, coverage proof, in-run redundancy proof) applies the decisions. This plan only supplies
its input. HARM-07 code changes and the actual 10b re-run are in Plan 15-02.

Purpose: HARM-04 is explicitly a decision that a human confirms and a program applies. It
cannot be automated -- the program must never invent a canonical-name mapping.
Output: extended `docs/concept_decisions.csv`, PCM-D-13 entry in `docs/DECISIONS.md`.
</objective>

<!-- The schema 10b_concept_harmonize.sas REQUIRES in concept_decisions.csv. -->
<!-- Six headers are mandatory (checked by work.req_hdr gate); PRIORITY is optional -->
<!-- but REQUIRED whenever any concept has more than one source column, or the tie -->

concept_decisions.csv required headers (case-insensitive, must all be present):
  CONCEPT, VARNAME, VALUE_TXT, TARGET_VALUE, CONFIRMED, HARMONIZED_NAME
Optional but needed for multi-source concepts:
  PRIORITY   (positive integer; blank defaults to 1; distinct per source within a concept)

10b gate constraints that govern how rows must be filled:
  - CONFIRMED is upcased and compared to 'YES'. Only 'YES' rows act. Blank rows ignored.
  - Gate (k): confirmation is CONCEPT-LEVEL. Every row of a confirmed concept must be YES,
    or the whole concept left blank. Mixing YES and blank within one concept ABORTS.
  - Gate (b): HARMONIZED_NAME must start with 'h_', be a valid SAS V7 name, <= 28 chars
    (so the h_*_src companion fits in 32).
  - Gate (c): HARMONIZED_NAME must NOT collide with any existing column in
    g.master_data_merged (nor its _src companion).
  - Gate (h): two DIFFERENT source columns in one concept must NOT share a PRIORITY.
  - Gate (m): VALUE_TXT / TARGET_VALUE must contain NO quote (22x), '&', or '%'.
    VALUE_TXT must match the OBSERVED value exactly (SECTION 3 coverage), so a value that
    contains one of these characters CANNOT be harmonized by the current 10b at all --
    substituting the character in VALUE_TXT would break coverage. Such concepts are
    DEFERRED, not confirmed.
  - SECTION 3 coverage: EVERY observed value of each confirmed source column must be mapped,
    or the run aborts. Confirm a concept only if the EXT template enumerates all its values.

Pinned harmonized names (do not let the reviewer choose freely -- gate (c) is checked in 15-02):
  SSDI death family  -> h_ssdi_death
  CPT1 code/label    -> h_cpt1
  Label-similarity pairs -> h_<short concept noun>, <= 28 chars, agreed at Task 2
Use the CONCEPT identifiers exactly as they appear in the EXT template; do not rename them.
