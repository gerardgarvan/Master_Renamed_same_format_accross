<objective>
Wave 0 discovery. Before any join, domain assignment, or statistics can be planned concretely,
seven facts must be established from the live datasets: (1) the exact name of the year variable
in g.analysis_base plus its missingness and per-year N, (2) the exact set of frailty, cognitive,
and intraoperative-physiologic columns present in g.master_data_merged but NOT in g.analysis_base
(the KEEP= list for the D-01 join), (3) the stored TYPE and LENGTH of PRECEDE_STUDY_ID in both
datasets, (4) whether PRECEDE_STUDY_ID is unique in g.master_data_merged, (5) non-missing
coverage of the extension columns, (6) candidate identifier/technical-key columns, and (7) which
variables actually carry the -999 / literal NULL sentinels. This plan also lays down the reusable
program scaffold (config include, log routing, fail_out, precondition checks) that Waves 1-3 extend.

Purpose: Eliminate every RESEARCH open question so downstream waves plan against real metadata
instead of guesses. A wrong year-column guess silently breaks per-year stratification; a wrong
KEEP= list silently produces all-missing D3/frailty columns; an unknown key type forces the
executor into runtime type-branching code that will not compile; an unscoped sentinel list
destroys legitimate -999 values in variables that never used it as a sentinel.
Output: sas/17_summary_stats_by_domain.sas Sections 0-0b, plus qc/17_discovery.txt with the
answers written as committed text.
</objective>

Append Section 0b to sas/17_summary_stats_by_domain.sas. Write DISCOVERY code that answers every
RESEARCH open question and writes results to qc\17_discovery.txt. Concretely:

1. Inventory both datasets from dictionary.columns:
   `proc sql; create table work.cols_base as select upcase(name) as name length=32, type as vtype length=4, length as vlen, label as sas_label length=256 from dictionary.columns where libname='G' and memname='ANALYSIS_BASE'; create table work.cols_merged as select upcase(name) as name length=32, type as vtype length=4, length as vlen from dictionary.columns where libname='G' and memname='MASTER_DATA_MERGED'; quit;`

2. KEY METADATA (feeds the Wave 1 compile-safe cast). Capture the stored TYPE and LENGTH of
   PRECEDE_STUDY_ID in BOTH datasets into macro variables and write them to the discovery file:
   `proc sql noprint; select type, length into :key_type_base trimmed, :key_len_base trimmed from dictionary.columns where libname='G' and memname='ANALYSIS_BASE' and upcase(name)='PRECEDE_STUDY_ID'; select type, length into :key_type_merged trimmed, :key_len_merged trimmed from dictionary.columns where libname='G' and memname='MASTER_DATA_MERGED' and upcase(name)='PRECEDE_STUDY_ID'; quit;`
   NOTE for the record: a SAS variable has exactly ONE type per dataset. The md7 numeric-key
   history describes the SOURCE files, not g.master_data_merged, which now holds a single
   resolved type. Discovery reports that resolved type — Wave 1 generates its cast from it.
   Also sample and write 10 non-missing key values from EACH dataset verbatim, so leading-zero
   padding (or its absence) is visible before the cast format is chosen.

3. KEY UNIQUENESS. Count PRECEDE_STUDY_ID values occurring more than once in g.master_data_merged:
   `proc sql noprint; select count(*) into :n_key_dups trimmed from (select PRECEDE_STUDY_ID from g.master_data_merged group by PRECEDE_STUDY_ID having count(*) > 1); quit;`
   Write the count to the discovery file. A non-zero value is not a failure here — it is a fact
   Wave 1 must handle before merging (Wave 1 fails hard on it).

4. YEAR VARIABLE: identify candidate year columns in g.analysis_base by name pattern —
   `proc sql; create table work.year_candidates as select name, vtype, sas_label from work.cols_base where index(name,'YEAR')>0 or index(name,'_DATE')>0 or index(name,'SURG')>0 or index(name,'ENCOUNTER')>0; quit;`
   Write every candidate to qc\17_discovery.txt. For any numeric candidate whose name contains YEAR,
   also run PROC FREQ with `/ missing` to list distinct values AND the missing count. If a true year
   variable exists, capture its exact name into a note and record: distinct year values, N per year,
   N missing year, and any implausible value (negative, 0, -999, outside 2015-2026). If NONE exists,
   write an explicit line "NO YEAR COLUMN FOUND — per-year stratification must derive year from a
   surgery-date column: <list date candidates>". Do NOT guess a name — report what is present.

5. EXTENSION COLUMN LIST (D-01 KEEP=): compute columns present in g.master_data_merged but NOT in
   g.analysis_base, restricted to the frailty/cognitive/intraop-physiologic concepts. Use ANCHORED
   patterns — a bare `index(name,'MAC')` matches STOMACH and PHARMACY, so match MAC only as a whole
   word or prefixed token:
   `proc sql; create table work.ext_candidates as select m.name, m.vtype from work.cols_merged m where m.name not in (select name from work.cols_base) and (index(m.name,'FRAIL')>0 or index(m.name,'COGNI')>0 or index(m.name,'FEELS')>0 or index(m.name,'WEIGHT_LOSS')>0 or index(m.name,'GRIP')>0 or index(m.name,'WALK')>0 or index(m.name,'PHYSICAL_ACTIV')>0 or index(m.name,'ABP')>0 or index(m.name,'BIS_')>0 or index(m.name,'NIBP')>0 or index(m.name,'MIDAZOLAM')>0 or prxmatch('/(^|_)MAC(_|$)/', strip(m.name))>0 or index(m.name,'ISO_SEV')>0); quit;`
   EXCLUDE `PRECEDE_STUDY_ID_1` explicitly (md6 duplicate, per pitfall). Write the full resolved list
   to qc\17_discovery.txt as the authoritative KEEP= list for Wave 1's join. Write it in a form that
   can be pasted directly as a KEEP= list AND also leave work.ext_candidates in WORK so Wave 1 can
   build `&extension_keep_list` dynamically instead of transcribing it by hand.

6. EXTENSION COVERAGE (D3 / frailty denominator). For every column in work.ext_candidates, count
   non-missing values in g.master_data_merged and write `varname, n_nonmissing, pct_of_base_rows`
   to the discovery file. This answers whether cognitive assessment covers the whole 41,150-row
   base or only a PRECEDE subcohort. If coverage is materially below the base row count, Wave 1
   must state a separate denominator for D3 and the D2 frailty block, and Wave 3 must note it on
   the KEY sheet. Flag this explicitly in the discovery file as
   "PARTIAL COVERAGE — D3/frailty require a stated denominator" when any extension column covers
   less than 90 percent of base rows.

7. IDENTIFIER CANDIDATES. List columns that look like identifiers or technical keys so Wave 1 can
   mark them OUT_OF_SCOPE rather than summarize them. An ID sent to PROC FREQ produces a table with
   tens of thousands of levels and an unusable Excel sheet. Match on name pattern —
   `where index(name,'_ID')>0 or index(name,'ID_')>0 or name in ('PRECEDE_STUDY_ID','ENCRYPTED_MRN','ENCRYPTED_ENCOUNTER') or index(name,'MRN')>0 or index(name,'ENCOUNTER')>0`
   — and additionally report, for every character variable, its distinct level count via
   `proc freq nlevels` so that any variable with more than 200 levels is surfaced regardless of name.
   Write both lists to the discovery file.

8. SENTINEL APPLICABILITY. Do NOT assume -999 and literal NULL are global reserved codes. For every
   numeric column in g.analysis_base, count rows equal to -999; for every character column, count
   rows where `upcase(strip(x))='NULL'`. Write only the variables with a non-zero count to
   qc\17_discovery.txt as the authoritative sentinel applicability list. Wave 2 recodes ONLY the
   variables on this list. Implement with a `proc freq` / `proc sql` loop inside a named macro.

9. IN-DATA-ONLY / DEFECT scan: flag any column in g.analysis_base matching the regex-equivalent
   pattern `VAR` followed by digits (positional XLSX defect) —
   `where prxmatch('/^VAR\d+$/', strip(name))` — and write the count to qc\17_discovery.txt.

10. Write qc\17_discovery.txt via `data _null_; file "&qc_path.\17_discovery.txt"; ...` including:
    run datetime, n_base_rows, key type/length in both datasets plus sampled key values, key
    duplicate count, the year-variable finding with per-year N and missing count, the count and
    full list of extension columns, extension coverage with the partial-coverage flag, identifier
    candidates and high-cardinality variables, the sentinel applicability list, and the VARnn defect
    count. Use only PUT text without apostrophes or embedded semicolons in %PUT.

This section produces NO permanent datasets and writes nothing to g. It is read-only discovery.
