<objective>
Wave 3 (spec §5). Assemble the single deliverable workbook with ODS EXCEL: KEY sheet leftmost,
then D1-D5 domain sheets from the Wave 2 display datasets, then Crosswalk and QC sheets. Apply
UF colors to header rows and group per-year columns under spanning headers. Write the parallel QC
text artifact. Verify both deliverables exist, then restore the log. End at a blocking human review
of the issued workbook against the data dictionary (Checkpoint 2).

Purpose: This turns the computed statistics and the domain map into the one artifact the team
consumes. KEY-leftmost and UF colors are project conventions (CLAUDE.md). The QC sheet is where
the phase proves it did what it claims — recode counts, suppression counts, per-rule assignment
counts. Three traps: a locked prior workbook; the ODS EXCEL default sheet_interval, which splits
a domain's two PROC REPORT calls onto 'D1' and 'D1 1' instead of one tab; and validating outputs
after %restore_log, which is backwards since %fail_out itself calls %restore_log.
Output: qc\17_summary_stats_by_domain.xlsx (KEY, D1-D5, Crosswalk, QC), qc\17_summary_stats_by_domain.txt,
and Checkpoint 2 approval.
</objective>

SECTION 9 — WORKBOOK. First a `%drop_stale` macro deleting a prior qc\17_summary_stats_by_domain.xlsx
via filename/fdelete, calling %fail_out if rc ne 0 (copy lines 362-373 of 16_summary_docx.sas,
new file name). Then:

1. `ods listing close;` and open ODS EXCEL ONCE, with sheet_interval held off:
   `ods excel file="&qc_path.\17_summary_stats_by_domain.xlsx" options(sheet_name="KEY" embedded_titles="yes" autofilter="all" frozen_headers="1" sheet_interval="none");`
   SHEET_INTERVAL IS LOAD-BEARING. Under the default ("table") every PROC REPORT begins a new sheet,
   so a domain's continuous table lands on "D1" and its categorical table on "D1 1" — the workbook
   ends up with fifteen tabs instead of eight and fails Checkpoint 2 on structure. Hold
   sheet_interval="none" for the whole run and move tabs only by changing sheet_name.

2. KEY sheet FIRST (makes it leftmost). Build a work.key dataset (item/detail rows) and PROC REPORT
   it with `style(header)=[background=CX0021A5 color=white fontweight=bold]`. Include:
   - legend of the statistic set (continuous and categorical)
   - dataset name (work.analysis_base_ext, derived from g.analysis_base + g.master_data_merged)
   - run datetime and row count (&n_base_rows)
   - suppression rule stated in the same terms the sheets use: "cells representing &SUPPRESS_MAX or
     fewer patients are shown as &SUPPRESS_LABEL; for continuous blocks at or below that count, all
     statistics for the block are suppressed, not only the count"
   - denominator rule (percent on non-missing per D-02, with n missing reported separately)
   - the D3/frailty denominator note from 17-02-SUMMARY.md when coverage is PARTIAL: state plainly
     that D3 and the D2 frailty block are computed on the assessed subcohort, give its N, and say
     that it differs from the D1/D4/D5 population. Without this the reader sees ~95 percent missing
     and concludes the data are broken rather than that the population differs.
   - scope statement (descriptive only, no inferential testing)

3. D1 through D5: for each domain switch sheet with `ods excel options(sheet_name="D1");` (D2..D5
   likewise) and PROC REPORT the domain's continuous display dataset then its categorical display
   dataset — both land on the same tab because sheet_interval is none. Use the UF blue header style
   on both. Group the pooled and per-year column blocks under SPANNING HEADERS rather than emitting
   one flat run of ~99 columns:
   `column ("Pooled" n_pool mean_pool std_pool median_pool q1_pool q3_pool min_pool max_pool) ("2018" n_2018 mean_2018 ...) ("2019" ...);`
   Generate the spanning column list with a macro loop over the year values from 17-01-SUMMARY.md.
   Add the D5 note about _30_DAY_MORTALITY missingness reflecting the md1 join, not the outcome
   (pitfall 6). On D3 and the D2 frailty rows, repeat the subcohort denominator note.

4. Crosswalk sheet: `ods excel options(sheet_name="Crosswalk");` PROC REPORT g.var_domain_map with
   columns varname, sas_label (dictionary label), vtype, n_levels, stat_route, source_dataset,
   domain, domain_rationale, denominator_note — ordered by domain then varname, UF blue header.
   OUT_OF_SCOPE rows (identifiers, high-cardinality keys, not-in-dictionary) appear here with their
   reason: they are excluded from statistics, not from documentation.

5. QC sheet: `ods excel options(sheet_name="QC");` PROC REPORT a work.qc_summary dataset built from:
   source dataset name, row count, run datetime, per-variable sentinel recode counts from
   work.sentinel_log (list them — a variable nobody expected to carry a sentinel is a finding),
   total recodes, :n_suppressed with its split by cause, count of variables per domain, count of
   OUT_OF_SCOPE by reason, and count of variables by each of the three assignment rules
   (assign_rule in 'timing'/'analytic_role'/'instrument').

6. `ods excel close; ods listing;`

SECTION 10 — QC TEXT ARTIFACT. `data _null_; file "&qc_path.\17_summary_stats_by_domain.txt"; ...`
writing the same QC facts as plain text (run datetime, source, row count, per-domain counts,
per-rule counts, OUT_OF_SCOPE by reason, total recodes, suppressed cells, D3 denominator verdict).
No apostrophes or embedded semicolons in any %PUT.

SECTION 11 — VERIFY, THEN RESTORE. Order matters: %fail_out itself calls %restore_log, so validating
after the log is already restored is backwards. Check both deliverables first, then restore:
```sas
%check_xlsx;      /* fileexist on qc\17_summary_stats_by_domain.xlsx, else %fail_out */
%check_qc_txt;    /* fileexist on qc\17_summary_stats_by_domain.txt,  else %fail_out */
%restore_log;
```
Both checks are named macros calling %fail_out. All conditional logic in named macros; %abort cancel
only via %fail_out.
