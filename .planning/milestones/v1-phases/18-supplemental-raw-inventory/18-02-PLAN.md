In 18: `%gate_d15;` is the last executable line before the trailing `%restore_log;`.
In 17: `%gate_d15;` is placed immediately before the step that creates work.analysis_base_ext.
%fail_out already exists in both programs and contains the only %abort cancel in each.

Missing-value rule (apply to EVERY raw value before any count):
```sas
/* numeric raw value */   raw_miss = (missing(raw_val) or raw_val = -999);
/* character raw value */ raw_miss = (missing(raw_val) or upcase(strip(raw_val)) = 'NULL');
```
-999 is the project-wide missing sentinel in the clock/dCDT variables; the literal string NULL
was the sentinel that forced master_data_8 columns to CHAR. Neither is caught by missing().

Type-safe equality (per IN_BASE column, one merge per column, never wide):
```sas
data work.gap_one;
  merge work.base_k(keep=_k &col rename=(&col=base_val) in=inb)
        work.raw_k (keep=_k &col rename=(&col=raw_val)  in=inr);
  by _k;
  if inb and inr;                       /* matched IDs only */
  length _r $200 _b $200;
  _r = strip(cats(raw_val));  _b = strip(cats(base_val));
  raw_miss  = <rule above, by raw type>;
  base_miss = missing(base_val);
  fillable  = (base_miss and not raw_miss);
  equal     = (not raw_miss and not base_miss and _r = _b);
  conflict  = (not raw_miss and not base_miss and _r ne _b);
run;
```
When raw and base types differ for the same column, every non-missing pair will land in
conflict (a numeric date renders as 21550, a char date as 01JAN2019). That is why raw_type and
base_type are carried into the results: the reader must be able to see that a conflict count is
a type artefact.
