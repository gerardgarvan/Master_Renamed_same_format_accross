md6 SECTION 2b (PROVE the duplicate before dropping it -- runs BEFORE the DATA step):
```sas
/* PCM-D-06 is recorded as "resolved as drop" on the claim that PRECEDE_Study_ID_1 is
   identical to PRECEDE_STUDY_ID in every row. That comparison may never actually have
   been executed. Prove it here: if the columns differ anywhere, the column is NOT a
   duplicate and dropping it destroys information.                                      */
proc sql noprint;
  select count(*) into :n_keydiff trimmed from src.master_data_6
  where PRECEDE_STUDY_ID ne PRECEDE_Study_ID_1;
quit;
%macro assert_dup_identical;
  %if &n_keydiff > 0 %then %do;
    %put ERROR: PREP-04 VIOLATION -- PRECEDE_Study_ID_1 differs from PRECEDE_STUDY_ID in &n_keydiff rows.;
    %put ERROR- It is NOT a duplicate. Dropping it would destroy data. Re-open PCM-D-06.;
    %abort cancel;
  %end;
  %else %put NOTE: PREP-04 OK -- PRECEDE_Study_ID_1 identical to PRECEDE_STUDY_ID in all rows; safe to drop.;
%mend assert_dup_identical;
%assert_dup_identical;
```

md6 SECTION 3 (add the PREP-07 conversion and the DROP inside the DATA step):
```sas
data g.prep_md6;
  length
    PRECEDE_STUDY_ID $12
    Base_Procedure_Code_1 $10   /* PREP-07: NUM in md6, CHAR $10 in md1/2/3/8 */
    /* EVERY md6 character variable EXCEPT PRECEDE_Study_ID_1 (it is being dropped) */
    ;
  set src.master_data_6 (rename=(Base_Procedure_Code_1=_bpc_n));
  if not missing(_bpc_n) then Base_Procedure_Code_1 = strip(put(_bpc_n, best12.));
  drop _bpc_n;
  drop PRECEDE_Study_ID_1;   /* PREP-04 / PCM-D-06: duplicate, proven identical above */
run;
```
PREP-07 applies to md4, md5 and md6 alike (all three carry `Base_Procedure_Code_1` as NUM).
Convert toward CHARACTER, never the reverse: `input()` on a code with a leading zero or an
alphabetic character destroys it, while `put(...,best12.)` + `strip()` is lossless in this
direction. Declare the `$10` target in the LENGTH block BEFORE the SET, and rename the incoming
numeric out of the way so the two never collide in the PDV.
Do NOT declare PRECEDE_Study_ID_1 in the LENGTH block — it is dropped, so declaring it would
re-create it as a zero-value column.

