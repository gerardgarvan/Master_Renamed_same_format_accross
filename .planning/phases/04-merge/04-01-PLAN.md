OWNERSHIP RESOLUTION RULE (mechanical -- apply in code, not by hand):
  1. If md3 carries the variable, md3 owns it (spine; 41,150 rows -- its value is present for
     every patient in the merged file).
  2. Otherwise the contributing source with the highest row count owns it.
     Row counts: md3=41150 > md8=22473 > md1=md2=14778 > md6=9462 > md7=9215 > md4=md5=7695.
  3. Ties broken by lowest source number (md1 before md2; md4 before md5).

This rule reproduces every assignment the hand-written table specified, including the ones that
looked like exceptions: FEELS_EXAUSTED and the other four frailty components go to md7 (md6 and
md7 both carry them; md6=9462 > md7=9215, so rule 2 gives md6 -- SEE NOTE BELOW),
ICD10_PRINCIPAL_DIAGNOSIS_POA to md6, SSDI_DEATH_Y_N to md6, SORT_ID to md4, _30_DAY_MORTALITY
to md1.

NOTE -- ONE GENUINE EXCEPTION requiring an explicit override in the resolution code:
  FEELS_EXAUSTED, LOW_PHYSICAL_ACTIVITY, SLOW_WALKING_SPEED, UNINTENDED_WEIGHT_LOSS,
  WEEK_GRIP_STRENGTH are $3 in md7 and $1 in md6. Rule 2 would pick md6 (more rows), but md6's
  $1 width cannot hold md7's 3-character values, and these are the same five frailty items.
  Override the owner to md7 for these five, and record the override in docs/DECISIONS.md.
  A width difference is the signal that two sources are NOT storing the same encoding --

SECTION 2b — Resolve ownership and generate the KEEP= lists.

Read `qclib.ownership_map` (Phase 2 artifact in the qc library), apply the resolution rule from
the interfaces block, write the resolved owner back to a work copy, and build one macro variable
per source. If the Phase 2 map still carries the literal `CONFLICT` in its owner column, resolve
it here — a `CONFLICT` value reaching the keep-list builder is an ERROR, not a default.

```sas
libname qclib "&qc_path";

/* Resolve owner: md3 if present, else highest-row-count source, ties to lowest number,
   with the five frailty-component overrides to md7 (width signal -- see interfaces). */
data work.ownership_resolved;
  set qclib.ownership_map;
  length owner_resolved $4;
  /* sources_present is the pipe-delimited list built in Phase 2, e.g. 'md3|md6|md7' */
  if      index(sources_present,'md3') then owner_resolved = 'md3';
  else if index(sources_present,'md8') then owner_resolved = 'md8';
  else if index(sources_present,'md1') then owner_resolved = 'md1';
  else if index(sources_present,'md2') then owner_resolved = 'md2';
  else if index(sources_present,'md6') then owner_resolved = 'md6';
  else if index(sources_present,'md7') then owner_resolved = 'md7';
  else if index(sources_present,'md4') then owner_resolved = 'md4';
  else if index(sources_present,'md5') then owner_resolved = 'md5';

  /* PCM-D-02 override: these five are $3 in md7 and $1 in md6. md6 wins on row count but
     cannot hold md7's values. Width mismatch means the encodings differ -- take md7.        */
  if upcase(varname) in ('FEELS_EXAUSTED','LOW_PHYSICAL_ACTIVITY','SLOW_WALKING_SPEED',
                         'UNINTENDED_WEIGHT_LOSS','WEEK_GRIP_STRENGTH')
     then owner_resolved = 'md7';

  /* Dropped in Phase 3 PREP-04 -- must never reach a keep list */
  if upcase(varname) = 'PRECEDE_STUDY_ID_1' then delete;
  if upcase(varname) = 'PRECEDE_STUDY_ID'   then delete;   /* key: kept explicitly on all 8 */
run;

/* Guard: every variable must have exactly one resolved owner */
proc sql noprint;
  select count(*) into :n_unresolved trimmed
  from work.ownership_resolved where missing(owner_resolved);
quit;
%macro assert_resolved;
  %if &n_unresolved > 0 %then %do;
    %put ERROR: MRG-04 -- &n_unresolved variables have no resolved owner. Check sources_present.;
    %abort cancel;
  %end;
  %else %put NOTE: MRG-04 OK -- every mapped variable has exactly one owner.;
%mend assert_resolved;
%assert_resolved;

%macro build_keeplists;
  %local i;
  %do i = 1 %to 8;
    %global keep&i;
    proc sql noprint;
      select varname into :keep&i separated by ' '
      from work.ownership_resolved where owner_resolved = "md&i";
    quit;
    %put NOTE: md&i owns %sysfunc(countw(&&keep&i)) variables.;
  %end;
%mend build_keeplists;
%build_keeplists;
```

SECTION 3 — Spine-first DATA step merge with generated KEEP= lists:

LENGTH block — declare each character variable at its **OWNER's** width, taken from that
owner's row in `qc/03_charvars_all.txt`. Do NOT use the max across sources: under KEEP= only the
owner's copy reaches the merge, so a max-width declaration is both wasteful and misleading.
Examples that change under this rule: `Emergent $1` (md3 owns; md8's `$4` is not kept),
`Intraop_Ketamine $1`, `Preop_block $1`, `Feels_Exausted $3` (md7 owns), `Race $16` (md3),
`ENCRYPTED_ENCOUNTER $49` (md3), `Base_Procedure_1 $199` (md3), `Dischg_Disposition $43` (md3).

Also declare the nine provenance variables (`in_md1`–`in_md8`, `n_sources`) and
`rt_envelope_flag` (MRG-05), each numeric length 3.

MERGE statement — md3 FIRST (spine, MRG-04, PCM-F-02), every source with `IN=` and `KEEP=`:
```sas
data g.master_data_merged;
  length
    PRECEDE_STUDY_ID $12
    /* ... every character variable at its OWNER's width ... */
    in_md1 3 in_md2 3 in_md3 3 in_md4 3
    in_md5 3 in_md6 3 in_md7 3 in_md8 3 n_sources 3
    rt_envelope_flag 3                       /* MRG-05 -- see the derivation below */
    ;
  merge
    work.sort_prep_md3 (in=in3 keep=PRECEDE_STUDY_ID &keep3)   /* SPINE -- MUST be first */
    work.sort_prep_md1 (in=in1 keep=PRECEDE_STUDY_ID &keep1)
    work.sort_prep_md2 (in=in2 keep=PRECEDE_STUDY_ID &keep2)
    work.sort_prep_md4 (in=in4 keep=PRECEDE_STUDY_ID &keep4)
    work.sort_prep_md5 (in=in5 keep=PRECEDE_STUDY_ID &keep5)
    work.sort_prep_md6 (in=in6 keep=PRECEDE_STUDY_ID &keep6)
    work.sort_prep_md7 (in=in7 keep=PRECEDE_STUDY_ID &keep7)
    work.sort_prep_md8 (in=in8 keep=PRECEDE_STUDY_ID &keep8)
    ;
  by PRECEDE_STUDY_ID;

  in_md1 = in1; in_md2 = in2; in_md3 = in3; in_md4 = in4;
  in_md5 = in5; in_md6 = in6; in_md7 = in7; in_md8 = in8;

     occupancy containing it is impossible, but each of the three timestamps is
     individually plausible and nothing identifies which one is wrong. FLAG, do not
     null -- nulling destroys two good values to punish one bad one. 9 rows expected.

     Derived HERE and not in Phase 3 prep: the ownership map is built in Phase 2 from
     the SOURCE files, so a variable invented during prep is not in it, and MRG-04
     asserts zero unmapped columns. A prep-created flag would fail that assertion.

     Both sides guarded (PCM-T-11): `a > b` is TRUE when b is missing.              */
  rt_envelope_flag =
     ( rt_RM_START_to_RM_END_mins is not missing
       and ( (rt_INCISE_to_DRESS_mins is not missing
              and rt_INCISE_to_DRESS_mins > rt_RM_START_to_RM_END_mins)
          or (rt_RM_START_to_INCISION_mins is not missing
              and rt_RM_START_to_INCISION_mins > rt_RM_START_to_RM_END_mins) ) );
  label rt_envelope_flag = 'Operative sub-interval exceeds room interval (1=yes)';
run;
```

No-surviving-NULL assertion (Pattern 4 from RESEARCH.md) -- scope it to md8-OWNED columns only.

An earlier draft enumerated `Race`, `Ethnicity`, `Sex`, `Marital_Status`, `EmployeeStatus` and
similar. Under KEEP= ownership md3 owns all of those, so md8's copies never reach the merged
file — the scan would test md3's values for a sentinel md3 never had and report 0 regardless of
the data. Derive the risk surface instead:

```sas
proc sql noprint;
  select count(*) into :n_md8_char trimmed
  from dictionary.columns
  where libname='G' and memname='MASTER_DATA_MERGED' and type='char'
    and upcase(name) in (select upcase(varname) from work.ownership_resolved
                         where owner_resolved='md8');

  select name into :md8_charvars separated by ' '
  from dictionary.columns
  where libname='G' and memname='MASTER_DATA_MERGED' and type='char'
    and upcase(name) in (select upcase(varname) from work.ownership_resolved
                         where owner_resolved='md8');
quit;

%macro null_scan;
  %if &n_md8_char = 0 %then %do;
    %put NOTE: MRG -- md8 owns no character variables in the merged file;
    %put NOTE- the NULL sentinel is unreachable by construction. Nothing to scan.;
    %let n_null_merged = 0;
  %end;
  %else %do;
    data _null_;
      set g.master_data_merged end=eof;
      retain _n_null 0;
      array _m8 {*} &md8_charvars;
      do _i = 1 to dim(_m8);
        if strip(upcase(_m8{_i})) = 'NULL' then _n_null + 1;
      end;
      if eof then call symputx('n_null_merged', _n_null, 'G');
    run;
  %end;
%mend null_scan;
%null_scan;
%assert_eq(actual=&n_null_merged, expected=0, label=surviving NULL sentinel strings);
```

hemodynamic block, which is entirely numeric. That is a legitimate and stronger result than a
scan. Do NOT manufacture a passing assertion over columns md8 does not own.
