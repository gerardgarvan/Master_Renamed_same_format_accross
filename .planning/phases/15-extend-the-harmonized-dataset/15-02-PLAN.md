<objective>
Satisfy HARM-07: state a rule governing pipeline-derived columns and enforce it in code, then
re-run `10b_concept_harmonize.sas` end-to-end so the extended decisions from Plan 15-01 are
applied and the no-information columns are provably dropped.

The rule drops `in_md3` (constant) and every `h_*_src` companion. The original justification
for the companions -- "no secondary source ever fires, so each holds one repeated value" --
was proven for the original 11 concepts only. Plan 15-01 adds concepts (SSDI has three
sources), and the drop loop runs over ALL of `&hnames`. If SECTION 4b does not prove a new
secondary redundant, that secondary stays in the file and CAN fire, and its `_src` companion
then carries provenance the rule would destroy. So the drop is made self-proving: the DATA
step writes the companions to a `work.src_check` side output, and SECTION 6 asserts each one
is single-valued before the run may pass.

Code changes to `sas/10b_concept_harmonize.sas` (no new program):
  1. Rule in the header + `%let drop_pipeline_noinfo = 1;` gate + dataset-option DROP on the
     SECTION 5 DATA statement, with a `work.src_check` side output keeping the companions.
  2. SECTION 6: `%assert_src_single` (premise), `%assert_harm07` (absence), `src_changed`
     exclusion for `in_md3`, and `%assert_merged_unchanged` (post-run 176 cols AND 41,150 rows).
  3. PCM-D-14 in docs/DECISIONS.md attributing the rule.

Then a human-verified fresh-session SAS run confirms everything passes.

Note on waves: Tasks 1-3 do not depend on Plan 15-01, but Task 4 (the SAS run) applies the
decisions Plan 15-01 wrote into concept_decisions.csv, so this plan runs in Wave 2.

Purpose: HARM-07 requires the rule to be "enforced in code" -- a comment satisfies "written"
but not "enforced". The DROP + premise assertion + absence assertion is the enforcement.
