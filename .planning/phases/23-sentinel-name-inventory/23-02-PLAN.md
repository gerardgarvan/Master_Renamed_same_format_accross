    Append SECTION 6 to sas/23_pcnr_inventory.sas.

    Step A -- read concept_decisions.csv with a DATA step infile (NOT PROC IMPORT, PCM-T-16) using
    explicit $ informats for every column. Keep distinct pairs where harmonized_name starts with 'h_'.
    Build a lookup set of raw varnames to mark DROP (these raw columns are superseded by an h_* column).

    Step B -- pull ALL columns of g.master_data_harmonized from dictionary.columns (name, label, type,
    length). One row per source column (completeness).

    Step C -- assign role:
      - role='KEY' if source_name in (pecan_ID, PRECEDE_STUDY_ID, ENCRYPTED_MRN, ENCRYPTED_ENCOUNTER)
        [case-insensitive compare]. final_name blank.
      - role='DROP' if source_name is in the Step A DROP set. final_name blank.
      - else role='KEEP'.

    Step D -- for KEEP rows build proposed_name (decision D-05, PCM-D-23):
      1. h_strip: if source_name starts with 'h_' set h_strip='Y' and base = substr(source_name,3);
         else h_strip='N', base = source_name.  (Strip h_ then prefix pcnr_ -- the h_ raw counterpart
         is separately marked DROP in Step C.)
      2. candidate = 'pcnr_' || base.
      3. If length(candidate) <= 32 -> proposed_name = candidate (no truncation).
      4. Else apply the truncation algorithm:
         - final_token = the substring after the LAST '_' in base.
         - if base has an underscore AND length(final_token) <= 12:
             budget = 32 - length('pcnr_') - 1 - length(final_token)   /* chars for head */
             head_src = base minus ('_'||final_token) at the end
             head = substr(head_src, 1, budget)
             proposed_name = 'pcnr_' || head || '_' || final_token
         - else (no underscore OR final_token > 12): proposed_name = substr('pcnr_'||base, 1, 32)  /* tail truncation */
      Worked example to verify against (from 23-RESEARCH.md): source name
      `rt_BLOCK_START_TO_BLOCK_END_mins` (32) -> `pcnr_rt_BLOCK_START_TO_BLO_mins` (31 chars).
      Add this example as a comment in the code so the reviewer can confirm at the PCM-D-23 checkpoint.

    Step E -- override_name left blank (human fills at checkpoint).
      final_name = coalescec(override_name, proposed_name) for KEEP rows; blank for KEY and DROP.
      name_len = length(final_name).

    Step F -- collision_flag: 1 when upcase(final_name) matches another KEEP row's final_name
      (use the PROC SQL self-join from 23-RESEARCH.md "Collision Detection for Name Map"). Blank/0 otherwise.

    Step G -- id_flag (separate column): 1 for any KEEP row whose source_name matches `*_ID`,
      `*STUDY_ID*`, or `ENCRYPTED_*` (case-insensitive) and is NOT on the KEY list. Surfaces leaks
      like PRECEDE_Study_ID_1.

    Export to `&qc_path.\23_pcnr_name_map_DRAFT.csv` in the exact D-05 column order:
      source_name source_label role h_strip proposed_name override_name final_name name_len collision_flag id_flag

    Validation (%put NOTE + assertions; abort via %fail_out on failure):
      - every source column appears exactly once (count = dictionary.columns count for the dataset)
      - max(name_len) over KEEP rows <= 32
      - count of collision_flag=1 rows (report; abort only if > 0 after proposed names -- but since
        overrides are blank at draft time, report the count as a NOTE and DO NOT abort at draft stage;
        the hard collision assertion runs in Phase 24 gate. Log the collision count clearly.)
      - DROP rows and KEY rows have blank final_name.
    Do NOT write to docs/.
  </action>
