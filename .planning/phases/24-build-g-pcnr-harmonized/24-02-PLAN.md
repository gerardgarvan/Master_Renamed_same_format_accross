  <action>
    Replace the SECTION 4 stub with a parallel-set comparison DATA step. Because character and
    numeric columns cannot share an array (SAS 9.4, Pitfall 2), build the arrays from metadata
    at generation time rather than hand-listing 175 columns: use PROC SQL against
    `dictionary.columns where libname='G' and memname='MASTER_DATA_HARMONIZED'` to build two
    macro variables — `&char_cols` (space-separated char column names) and `&num_cols`
    (numeric), both `order by varnum`. Then rename the recoded copy's columns to POSITIONAL
    names, not suffixed ones: the i-th char column becomes `_rc<i>` and the j-th numeric
    column `_rn<j>` (`&rec_rename_list` = `Race=_rc1 Sex=_rc2 ... Age_at_Encounter=_rn1 ...`,
    built from the same ordered query), and `&char_cols_r` = `_rc1-_rc&n_char`,
    `&num_cols_r` = `_rn1-_rn&n_num`. Suffixing (`<name>_r`) is not possible: ten source
    names are already 32 characters, the SAS maximum. Positional names also guarantee the
    source and recoded arrays line up element for element.

    ```sas
    /* ===== SECTION 4: full comparison ===== */
    data work._compare_out (keep=_n_row _chg_var _raw_value _raw_hex _authorized);
      set g.master_data_harmonized;                       /* source, by position */
      set work._recoded (rename=(&rec_rename_list));      /* recoded, all cols _r_ */
      length _chg_var $32 _raw_value $400 _raw_hex $800;
      array _src_c{*} $ &char_cols;
      array _rec_c{*} $ &char_cols_r;
      array _src_n{*}   &num_cols;
      array _rec_n{*}   &num_cols_r;
      _n_row = _n_;
      /* char columns */
      do _i = 1 to dim(_src_c);
        if _src_c{_i} ne _rec_c{_i} then do;
          _authorized = (missing(_rec_c{_i}));    /* recoded cell must be missing */
          _chg_var  = vname(_src_c{_i});
          _raw_value = _src_c{_i};
          _raw_hex   = %hexkey(_src_c{_i});
          /* authorization also requires (_chg_var,_raw_hex) in work._recode_rules -- via hash below */
          output;
        end;
      end;
      /* numeric columns */
      do _j = 1 to dim(_src_n);
        if _src_n{_j} ne _rec_n{_j} then do;
          _authorized = (missing(_rec_n{_j}));
          _chg_var  = vname(_src_n{_j});
          _raw_value = strip(put(_src_n{_j}, best32.));
          _raw_hex   = %hexkey(strip(put(_src_n{_j}, best32.)));
          output;
        end;
      end;
    run;
    ```
    Then verify authorization by joining `work._compare_out` to `work._recode_rules` on
    `(variable=_chg_var, raw_hex=_raw_hex)`. Any compare row where the recoded cell was NOT
    missing, OR the (_chg_var,_raw_hex) pair is absent from work._recode_rules, is an
    UNAUTHORIZED change. Count unauthorized rows into `:n_unauth trimmed`; a gate macro calls
    `%fail_out(msg=&n_unauth unauthorized cell changes)` when > 0.

    Cross-check 1: count total compare rows into `:n_compare_changes trimmed`; gate-macro
    `%fail_out` if `&n_compare_changes ne &n_recode_step_changes`.
    Cross-check 2: per (variable, raw_hex), the number of compare rows must equal `n_expected`
    (the `n_rows` from qc/23_sentinel_candidates.csv carried on work._recode_rules). Build a
    per-rule actual count from work._compare_out, join to work._recode_rules, and count rules
    where `actual ne n_expected` into `:n_drift trimmed`; `%fail_out` if > 0 (this is the
    source-drift check the fingerprint alone cannot catch).
    `%put NOTE: [24] comparison OK -- &n_compare_changes authorized changes;`.

    Note: the `keep=` option limits work._compare_out to the five working columns; without it
    every change row would also carry all 175 source and 175 recoded columns.
  </action>
