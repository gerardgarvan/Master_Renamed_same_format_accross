### Anti-Patterns to Avoid
- **Open-code %IF:** Any conditional outside a named macro causes "Expected %DO not found" parse failures (PCM-T-15; once broke 99_run_all.sas entirely)
- **PROC IMPORT for CSVs:** Banned (PCM-T-16) — DATA step infile only
- **&SQLOBS:** Use SELECT COUNT(*) INTO :n TRIMMED instead
- **file_id-based CSV row selection:** Use path-pattern selection (`index(full_path,'master')`) — file_ids can shift silently (lesson from Phase 27)
- **PHI in logs:** No min/max/sample for ENCRYPTED_MRN anywhere; enforce in every PUT and PROC SQL result
- **%local in open code:** PCM-T-15 — %local only inside macro definitions
- **data X; set X;:** Destroys dataset (PCM-T-02)
- **PROC SQL UPDATE:** Silent truncation trap (PCM-T-01)

## Common Pitfalls

### Pitfall 1: PHI Leakage via ENCRYPTED_MRN
**What goes wrong:** A PUT statement or PROC SQL result includes min/max values or sample values for ENCRYPTED_MRN in the log or CSV output.
**Why it happens:** Profiling ID columns with PROC MEANS or PROC SQL SELECT MIN/MAX is the natural approach; PHI guard applies to ENCRYPTED_MRN specifically.
**How to avoid:** Only compute and output width (length from dictionary.columns/PROC CONTENTS) and COUNT(*) WHERE NOT MISSING for ENCRYPTED_MRN. Add explicit comments in code marking the PHI guard for each column.
**Warning signs:** Any log line or CSV value containing what looks like an 18-character alphanumeric string for ENCRYPTED_MRN.

### Pitfall 2: Open-Code %IF Swallows Rest of File
**What goes wrong:** Placing `%if ... %then %let ...;` in open code causes "Expected %DO not found" and SAS silently stops processing.
**Why it happens:** SAS macro parser requires `%DO/%END` blocks in open code for %IF/%THEN with non-macro statements.
**How to avoid:** Wrap ALL conditional logic in named `%macro / %mend` blocks. See PCM-T-15. This has burned the project once (00_config.sas incident during v2.0).
**Warning signs:** Log shows macro resolution but no SECTION X notes after a conditional block.

### Pitfall 3: file_id-Based Row Selection Silently Selecting Wrong Rows
**What goes wrong:** Selecting rows from 19_raw_files.csv by `file_id = 5` picks the wrong file if the CSV was regenerated with a different ordering.
**Why it happens:** file_id values are assigned by program 19 and may not be stable across regenerations.
**How to avoid:** Always select by `filename` + `index(full_path, 'master')` path pattern (established in Phase 27 SHA pre-condition; see sas/27_md8_count.sas SECTION 3b).
**Warning signs:** SHA values look plausible but don't match expected byte sizes.

### Pitfall 4: Unprovenanced Match Rates in PCM-D-28
**What goes wrong:** Citing the 14.5%/64%/41% figures from PROJECT.md in PCM-D-28 without establishing which source pair, which key, which normalization, and what the denominator was.
**Why it happens:** PROJECT.md describes these rates narratively without traceable computation.
**How to avoid:** Check git log for the commit that introduced those figures, and read Phase 20/21 SUMMARY files. If provenance is found, document it explicitly. If not, do not cite the figures — cite only rates derived by the program.
**Warning signs:** PROJECT.md says "raw\ copies match the crosswalk at 14.5%, 64%, and 41%" with no commit SHA or program reference.

### Pitfall 5: Numeric-to-Character ID Normalization Producing Trailing Spaces
**What goes wrong:** PUT(numeric_id, best32.) produces a right-justified value with leading spaces; STRIP() removes them, but comparing `'1234'` vs `'001234'` still fails.
**Why it happens:** PRECEDE_STUDY_ID may be zero-padded character in some files and unpadded numeric in others.
**How to avoid:** After STRIP, check whether left-padding to a fixed width (e.g., compress to digits only, then compare as numeric) improves the match rate. Document which normalization was applied in the CSV row. Try direct match first, then stripped, then digit-only — document each.
**Warning signs:** n_matched = 0 when IDs look visually similar in log output.

### Pitfall 6: Block 3 md3-2022 Subset Defined Incorrectly
**What goes wrong:** Reading src.master_data_3 instead of the raw CSV; or not subsetting to YEAR=2022.
**Why it happens:** src.master_data_3 is convenient but the CONTEXT.md requires the raw CSV subset for reproducibility without src.master_data_3.
**How to avoid:** Read `&raw_path.\2018_2022_X_MASTER_DATASET_20240402.csv` via DATA step infile and filter where YEAR='2022' (or YEAR=2022 depending on type). Confirm nobs match expectation.
**Warning signs:** md3-2022 subset has more or fewer rows than expected for 2022 data.

### Block 2: PRECEDE_STUDY_ID Profile (type + width + non-missing count)
```sas
/* Discover type for r7 (src.master_data_7) */
proc contents data=src.master_data_7
  out=work._r7_meta(keep=name type length) noprint; run;

proc sql noprint;
  select type, length into :r7_id_type trimmed, :r7_id_len trimmed
  from work._r7_meta where upcase(name)='PRECEDE_STUDY_ID';

  /* Count non-missing -- safe for both numeric and character */
  select count(*) into :r7_id_count trimmed
  from src.master_data_7
  where not missing(PRECEDE_STUDY_ID)
    and (type(&r7_id_type) = 1 or upcase(strip(PRECEDE_STUDY_ID)) ne 'NULL');
quit;
%put NOTE: r7 PRECEDE_STUDY_ID type=&r7_id_type length=&r7_id_len nonmiss=&r7_id_count;

/* ENCRYPTED_MRN -- width and count ONLY (PHI guard) */
proc sql noprint;
  select length into :r7_mrn_len trimmed from work._r7_meta
  where upcase(name)='ENCRYPTED_MRN';
  select count(*) into :r7_mrn_count trimmed from src.master_data_7
  where not missing(ENCRYPTED_MRN)
    and upcase(strip(ENCRYPTED_MRN)) ne 'NULL';
quit;
%put NOTE: r7 ENCRYPTED_MRN length=&r7_mrn_len nonmiss=&r7_mrn_count [PHI guard -- no sample values];
```

### Block 3: Normalized Match Rate (numeric r7 vs character md3-2022)
```sas
/* Normalize r7 numeric ID to character */
proc sql noprint;
  create table work._r7_norm as
  select distinct strip(put(PRECEDE_STUDY_ID, best32.)) as id_c length=32
  from src.master_data_7
  where not missing(PRECEDE_STUDY_ID);

  /* md3-2022 subset (read from raw CSV, filter YEAR=2022) */
  /* ... (DATA step infile of 2018_2022 CSV, keep where YEAR='2022') ... */

  select count(*) into :n_left_r7 trimmed from work._r7_norm;
  select count(*) into :n_right_md3 trimmed from work._md3_2022;
  select count(*) into :n_matched_r7 trimmed
  from work._r7_norm as l
  inner join work._md3_2022 as r on l.id_c = r.id_c;
quit;

/* match_rate_left = n_matched / n_left; match_rate_right = n_matched / n_right */
%let mleft_r7  = %sysevalf(&n_matched_r7 / &n_left_r7,  float);
%let mright_r7 = %sysevalf(&n_matched_r7 / &n_right_md3, float);
%put NOTE: r7 vs md3-2022: n_left=&n_left_r7 n_right=&n_right_md3 n_matched=&n_matched_r7;
%put NOTE: match_rate_left=&mleft_r7 match_rate_right=&mright_r7;
```
