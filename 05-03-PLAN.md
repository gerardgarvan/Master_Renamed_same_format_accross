```sas
/* =========================================================================
   SECTION 5b: QC-06 -- operative sub-interval containment
   A range check tests one variable against a constant. It cannot see that
   rt_INCISE_to_DRESS_mins (positive, inside 0-2000) is LONGER than the room
   occupancy that contains it. 9 such rows exist (5 + 4, PCM-F-15) and every one
   passes QC-05. This is the check that catches them.

   PREP-08 nulls negatives only; it does not touch these rows and was never meant
   to. QC-06 is EXPECTED to fail at 9 until PCM-D-08 is decided. Do not widen a
   bound or relax this assertion to make the run green -- the rows are impossible,
   not extreme.

   IS NOT MISSING on BOTH sides (PCM-T-11): `a > b` is TRUE when b is missing,
   because missing sorts below every number. Without the envelope guard this
   would flag every row with no room interval recorded.
   ========================================================================= */
proc sql noprint;
  select count(*) into :n_env_rt1 trimmed
  from g.master_data_merged
  where rt_RM_START_to_RM_END_mins is not missing
    and rt_INCISE_to_DRESS_mins    is not missing
    and rt_INCISE_to_DRESS_mins > rt_RM_START_to_RM_END_mins;

  select count(*) into :n_env_rt2 trimmed
  from g.master_data_merged
  where rt_RM_START_to_RM_END_mins   is not missing
    and rt_RM_START_to_INCISION_mins is not missing
    and rt_RM_START_to_INCISION_mins > rt_RM_START_to_RM_END_mins;
quit;

%assert_eq(actual=&n_env_rt1, expected=0,
           label=QC-06 rt_INCISE_to_DRESS_mins exceeding room envelope);
%assert_eq(actual=&n_env_rt2, expected=0,
           label=QC-06 rt_RM_START_to_INCISION_mins exceeding room envelope);
```

Two separate assertions, not one combined count: when this fails you want to know which
sub-interval is at fault, and the first `%abort cancel` stops the program before the second
runs. Retrieve the unreached value with `%put &=n_env_rt2;` after an abort, exactly as was
done for the QC-05 time counts.

Both QC-05 time ceilings (2000 and 500) have never fired across 41,150 rows. That is either
because the data is well-behaved at the top end or because the bounds are too loose to be
useful, and nothing measured so far distinguishes those. This section produces the numbers.

```sas
/* =========================================================================
   SECTION 5c: operative-interval distribution -- REPORT ONLY (PCM-D-09)
   The QC-05 ceilings of 2000 and 500 minutes have never fired on any of the
   41,150 rows (PCM-F-16). Either the data is genuinely well-behaved or the
   bounds are decorative. This block measures the distribution so the decision
   is made on evidence, the way Admit_BMI's 10-100 was.
   NO ASSERTION HERE -- do not add one. Changing a bound is PCM-D-09, not this plan.
   ========================================================================= */
proc sql noprint;
  select count(*), min(rt_INCISE_to_DRESS_mins), max(rt_INCISE_to_DRESS_mins),
         mean(rt_INCISE_to_DRESS_mins)
    into :d1_n trimmed, :d1_min trimmed, :d1_max trimmed, :d1_mean trimmed
  from g.master_data_merged where rt_INCISE_to_DRESS_mins is not missing;

  select count(*), min(rt_RM_START_to_INCISION_mins), max(rt_RM_START_to_INCISION_mins),
         mean(rt_RM_START_to_INCISION_mins)
    into :d2_n trimmed, :d2_min trimmed, :d2_max trimmed, :d2_mean trimmed
  from g.master_data_merged where rt_RM_START_to_INCISION_mins is not missing;

  select count(*), min(rt_RM_START_to_RM_END_mins), max(rt_RM_START_to_RM_END_mins),
         mean(rt_RM_START_to_RM_END_mins)
    into :d3_n trimmed, :d3_min trimmed, :d3_max trimmed, :d3_mean trimmed
  from g.master_data_merged where rt_RM_START_to_RM_END_mins is not missing;
quit;

data _null_;
  file "&qc_path.\05_qc_merge_report.txt" mod;
  put "Operative-interval distribution (report only -- PCM-D-09):";
  put @1 "Variable" @36 "N" @44 "Min" @54 "Max" @66 "Mean" @78 "Current ceiling";
  put @1 "-------------------------------------------------------------------------------------------";
  put @1 "rt_INCISE_to_DRESS_mins"      @36 "&d1_n" @44 "&d1_min" @54 "&d1_max" @66 "&d1_mean" @78 "2000";
  put @1 "rt_RM_START_to_INCISION_mins" @36 "&d2_n" @44 "&d2_min" @54 "&d2_max" @66 "&d2_mean" @78 "500";
  put @1 "rt_RM_START_to_RM_END_mins"   @36 "&d3_n" @44 "&d3_min" @54 "&d3_max" @66 "&d3_mean" @78 "2000";
  put " ";
  put "Neither ceiling has ever fired. If Max sits far below the ceiling, the bound is";
  put "decorative -- recalibrate it against observed data or drop it and rely on QC-06.";
  put "If Max is close to the ceiling, the bound is doing real work. PCM-D-09 decides.";
run;
%put NOTE: PCM-D-09 -- operative-interval distribution written to the QC report (no assertion).;
```

Every aggregate is guarded with `IS NOT MISSING` in its WHERE clause. SAS aggregate functions
ignore missing values anyway, but the explicit guard makes `&dN_n` the count of *usable*
values, which is what the reader needs to interpret the min and max.
